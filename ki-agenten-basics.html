Der Unterschied: Chatbot vs. Agent

Der große Umbruch, der gerade passiert, ist der Wechsel von Chatbots zu Agenten. Ein Chatbot bekommt eine Frage und liefert eine Antwort — Ende der Geschichte. Ein Agent bekommt stattdessen einen Auftrag, arbeitet in Schleifen weiter, überprüft seine eigenen Zwischenergebnisse und bekommt Werkzeuge auf dem Rechner, mit denen er Dinge wirklich erledigt. Genau das ist die Autonomie, die man spürt, wenn man Claude Code, Codex oder Cursor benutzt.

Das Werkzeug, das so einen Agenten steuert, nennt man Agent Harness. Weil ein Agent tatsächlich handelt statt nur zu antworten, stellt sich sofort die Frage aus dem Titel dieser Seite: Wie sorge ich dafür, dass er nur vernünftige Dinge tut?

Chatbot

Auftrag rein → eine Antwort raus. Kein Zugriff auf deinen Rechner, keine eigene Handlung.

vs.

Agent

Auftrag rein → arbeitet in Schleifen, nutzt Tools, prüft sich selbst, bis das Ergebnis passt.

Kurz gesagtEin Agent handelt selbstständig mit echten Werkzeugen — deshalb lohnt sich ein Blick darauf, wie man ihn sicher einrichtet.

Läuft dein Agent lokal oder in der Cloud?

Bevor irgendetwas anderes wichtig wird, lohnt sich diese Unterscheidung: Arbeitest du im Browser mit einer Cloud-App (z. B. der ChatGPT-Web-App), oder mit einem Tool wie Claude Code, Codex oder Cursor, das als App direkt auf deinem Rechner läuft?

Ein Cloud-Agent lebt im Hintergrund bei einem Anbieter — der muss einiges an Aufwand betreiben, damit das zuverlässig funktioniert. Ein lokaler Agent dagegen greift direkt auf deine Projekte und Dateien zu. Beide Welten wachsen zwar zusammen, fühlen sich aber technisch und im Alltag noch spürbar unterschiedlich an.

Kurz gesagtCloud-Agenten sind bequemer und stärker abgesichert, lokale Agenten sind direkter mit deinen echten Dateien verbunden — und genau deshalb potenziell risikoreicher.

Memory & die Agent-Datei

Ein Agent nutzt ein sehr mächtiges Modell — aber jedes Modell braucht dauerhaften Kontext, zusätzlich zum einzelnen Prompt. Dafür gibt es eine globale Agent-Datei: Bei Claude Code heißt sie CLAUDE.md, bei anderen Tools AGENTS.md. Sie speichert zweierlei — Wissen über dich (Erinnerungen) und Wissen darüber, wie du arbeiten möchtest (Anweisungen).

Diese Datei liegt ganz banal als Textdatei lokal auf deinem Rechner, meist in einem versteckten Verzeichnis (auf dem Mac machst du das mit ⇧ ⌘ . sichtbar). Du musst sie nicht selbst schreiben: Du kannst den Agenten bitten, vergangene Chats auszuwerten, Vorschläge für die Datei zu machen — und das regelmäßig, etwa alle vier Wochen, zu wiederholen.

Daneben gibt es die eigentliche Memory: einzelne Fakten, die sich das Modell entweder merkt, weil du es ausdrücklich sagst, oder weil es sie selbst für wichtig hält. Anthropic und OpenAI setzen dabei bewusst auf eine persönliche Note, Google und Microsoft eher auf Zurückhaltung. Und weil Modelle dazu neigen, immer mehr hinzuzufügen, bleibt das Aufräumen vorerst deine Aufgabe — verlässlich von allein aussortieren können sie noch nicht.

50

Straßenschild-Prinzip: Eine Sicherheitsanweisung in der Agent-Datei ist wie ein Tempo-50-Schild. Der Agent könnte schneller fahren — er hält sich nur freiwillig daran, weil so die Anweisung lautet. Ein echter technischer Schutz ist das noch nicht (dazu später mehr bei Hooks).

Kurz gesagtCLAUDE.md/AGENTS.md ist der dauerhafte Kontext deines Agenten — lass sie dir vom Agenten selbst schreiben und pflegen, aber sieh sie als Empfehlung, nicht als Schutzmechanismus.

Skills — feste Anleitungen, die der Agent selbst erkennt

Wie bekommt ein Agent „Superkräfte" — Aufgaben zu übernehmen, die du sonst selbst machst? Der erste Baustein dafür ist ein Skill: ein festgelegtes Format für eine ausführliche Anleitung, das Modelle aus ihrem Training kennen. Technisch gesehen ist ein Skill nichts weiter als eine Textdatei mit einer detaillierten Beschreibung.

Das Besondere: Du musst im Prompt nicht jedes Mal erklären, wie eine Aufgabe abläuft. Der Agent durchsucht sein Skills-Verzeichnis selbst und entscheidet, ob gerade ein passender Skill vorhanden ist — auch ohne dass du ihn ausdrücklich erwähnst. Im Video etwa ein „Brand Vibe Checker", der prüft, ob ein Text oder eine Präsentation zum eigenen Marken-Stil passt.

Anthropic hat dieses Skills-Format zuerst entwickelt, andere Anbieter wie OpenAI sind mit eigenen, leicht abweichenden Standards nachgezogen. Skills lassen sich außerdem zentral verwalten und für ein ganzes Team ausrollen — praktisch, aber mit einem klaren Sicherheitshinweis: Skills aus fremden Quellen solltest du vor dem Einsatz einmal durchlesen, denn der Agent hält sich auch hier nur freiwillig an das, was darin steht.

Kurz gesagtEin Skill ist eine wiederverwendbare, vom Agenten selbst erkannte Anleitung für eine bestimmte Aufgabe — geprüft von dir, bevor sie zum Einsatz kommt.

MCP — das Handbuch fürs Werkzeug

Ein Skill sagt dem Agenten was zu tun ist — zum Beispiel „nutze Gmail". Aber woher weiß das Modell, wie es Gmail überhaupt bedient? Dafür gibt es MCP, das Model Context Protocol: ein offener Standard, mit dem eine KI lernt, wie sie ein bestimmtes Werkzeug benutzen soll.

MCP-Server sollten von vertrauenswürdigen, etablierten Anbietern stammen — theoretisch kann sie jeder erstellen, weil es ein offener Standard ist. Wie gut das Ergebnis am Ende wird, hängt sowohl von der Intelligenz des Modells als auch davon ab, was in diesem MCP-Server konkret steht.

📖

Handbuch-Prinzip: Stell dir vor, dein Agent soll Auto fahren, weiß aber nicht, wie das Auto bedient wird. MCP ist das Handbuch dazu: So gibst du Gas, so lenkst du. Die Regel „maximal 50 in der Stadt" steht dagegen in einem Skill oder der Agent-Datei — das Handbuch und die Regel sind zwei unterschiedliche Dinge.

Kurz gesagtMCP ist der Standard, über den ein Modell erst versteht, wie es ein Werkzeug technisch bedienen kann — nutze nur MCP-Server von Anbietern, denen du vertraust.
Fähigkeiten · ▶ 14:18 im Video

Plugins — Skills, MCP und Tools im Paket

Ein Plugin bündelt mehrere Bestandteile in einem Paket: mehrere Skills, ein oder mehrere MCP-Server und Tools. Ein Beispiel aus dem Video: Ein Security-Plugin für Codex enthält 13 Skills, einen MCP-Server und ein Tool — alles zusammen als ein Paket, das der Agent laden kann.

Der Grund dafür ist Übersichtlichkeit: Sobald du bei 100 oder 200 einzelnen Skills angekommen bist — und das geht schneller, als man denkt — wird es für den Agenten schwer, den richtigen im richtigen Moment zu finden. Ein Plugin ist eine weitere Bündelungsebene darüber. OpenAI hat gemeinsam mit Vercel, Cursor und weiteren Unternehmen dafür einen offenen Standard veröffentlicht.

Praktisch dabei: Mit einer „Record & Replay"-Funktion kann der Agent dir bei einer Aufgabe zusehen und daraus automatisch einen fertigen Skill bauen, der später Teil eines Plugins wird. Eine feste Regel, wie viele Plugins sinnvoll sind, gibt es nicht — wichtig ist, wie bei einem guten Mitarbeitenden, ein klar abgegrenzter Aufgabenbereich pro Plugin.

Kurz gesagtPlugins bringen Ordnung, sobald einzelne Skills und MCP-Server unübersichtlich werden — ein Paket mit klarem, engem Aufgabenbereich statt einem riesigen Sammelsurium.
Sicherheit · ▶ 17:12 im Video

Hooks & Sandbox — jetzt wird es technisch

Alles bisher Genannte — Agent-Datei, Memory, Skills, MCP — sind reine Textanweisungen. Straßenschilder eben, an die sich der Agent freiwillig hält. Die eigentlich spannende Frage ist: Was, wenn er es nicht tut? Könnte ein Agent auf deinem Rechner wirklich etwas löschen? Ja — wenn man es nicht technisch verhindert. Dafür gibt es zwei Mechanismen.

Ein Hook ist eine erzwungene, technische Sperre für bestimmte Befehle — zum Beispiel gegen destruktive Kommandos wie rm (löschen). Du findest Hooks in den meisten Agent-Werkzeugen unter den Entwickler- oder Programmier-Einstellungen, und falls du nicht weißt, wie man sie schreibt: Du kannst dein Agent-Werkzeug einfach selbst bitten, sinnvolle Hooks einzurichten und dir zu erklären, warum.

Eine Sandbox ist der zweite Mechanismus: ein klar abgegrenzter Arbeitsbereich. Der Agent darf sich darin frei bewegen, ihn aber nicht verlassen — wie eine Sandkiste. Anthropic und OpenAI verfolgen hier unterschiedliche Philosophien: Anthropic gibt dem Modell von Anfang an mehr Zugriff und verlässt sich stärker auf dessen Intelligenz, OpenAI arbeitet eher toolorientiert mit eigenen, engeren Sandboxes pro Agent.

⛔

Der Unterschied zum Straßenschild: Ein Hook ist wie eine technische Wegfahrsperre im Auto — du kannst noch so sehr aufs Gas treten, schneller als erlaubt geht es einfach nicht, bis jemand die Sperre bewusst abschaltet. Eine Sandbox ist die Sandkiste selbst: die Grenze, die der Agent gar nicht erst überschreiten kann.

Wie viel darf der Agent ohne Rückfrage tun? Dazu kommt eine letzte, sehr praktische Einstellung — die Berechtigungsstufe:

StandardDer Agent fragt bei jedem Schritt nach Erlaubnis. Langsam, aber sicher.
Auto ReviewWeitgehend automatisch, dieses Jahr deutlich besser geworden — höheres Risiko.
VollzugriffDer Agent handelt ohne Rückfrage. Nur einschalten, wenn du dir wirklich sicher bist.
Kurz gesagtHooks und Sandboxes sind der technische Unterbau, der Textanweisungen erst verlässlich macht — hier entscheidet sich, ob dein Agent nur „50 fahren soll" oder „technisch gar nicht schneller kann".
Fazit · ▶ 21:23 im Video

Und jetzt?

Wenn du bis hierhin gelesen hast, kennst du die Grundlagen, um mit einem Agenten sicher zu arbeiten: eine gepflegte Agent-Datei, sorgfältig ausgewählte Skills, vertrauenswürdige MCP-Server, sinnvoll gebündelte Plugins — und als technischen Unterbau Hooks und eine Sandbox, statt dich allein auf Textanweisungen zu verlassen.

Der praktische nächste Schritt: Verbinde nach und nach einzelne Tools, statt alles auf einmal freizuschalten. So merkst du mit der Zeit selbst am besten, was ein Agent dir wirklich zuverlässig abnehmen kann — und wann du lieber noch einmal nachfragst.

Kurz gesagtGrundlagen verstanden heißt: Schritt für Schritt ausprobieren statt alles auf einmal freizugeben.
